## Design Philosophy

This system prioritizes:

| Principle | Over | Because |
|---|---|---|
| Systems thinking | Tool memorization | Tools change; architectures endure |
| Failure modes | Happy paths | Production breaks in interesting ways |
| Governance | Speed | Ungoverned ML systems create liability |
| Observability | Blind deployment | You can't fix what you can't see |
| Reproducibility | Convenience | "It works on my machine" isn't engineering |
| Durable concepts | Procedural steps | Understanding transfers; commands don't |

---

## Who This Is For

- **Technical reviewers**: See consistent engineering practice and systems thinking
- **Hiring managers**: Assess production-readiness mindset via architecture and failure analysis
- **ML engineers**: Evaluate operational depth via playbooks and governance considerations
- **Future self**: A searchable, RAG-ready knowledge base for production ML decisions

---

## The Stack

### Operational Practice Layer
**KodeKloud 100 Days of MLOps**: DVC, MLflow, Feast, Kubernetes, Argo Workflows,
Evidently — real tools, real configurations, real failure modes.

### Engineering Journal Layer
**Databricks Student Edition**: Structured daily notebooks capturing not just what was
done, but why it matters, how it connects to production systems, and what would break
at scale.

### Knowledge Graph Layer
**Obsidian LLM Wiki**: Evergreen notes that extract durable concepts from daily practice
— linked, tagged, and structured for both human navigation and machine retrieval.

### Portfolio Layer
**GitHub**: Public-facing documentation demonstrating engineering capability through
architecture notes, debugging playbooks, and systematic learning evidence.

### Intelligence Layer (Future)
**RAG + NotebookLM**: Semantic search over accumulated MLOps knowledge, enabling
conversational querying and interview preparation.
